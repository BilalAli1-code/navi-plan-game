# Contributing to the ProjectSim 2.0 Blueprint

## Workflow

1. Create or link a GitHub issue.
2. Identify the affected document and requirement.
3. Create a branch.
4. Update the relevant Markdown files.
5. Add or update ADRs when decisions change.
6. Open a pull request.
7. Complete review before merge.

## Branch Naming

```text
docs/<short-description>
architecture/<short-description>
fix/<short-description>
```

## Commit Examples

```text
docs(product): expand learner personas
docs(domain): define simulation action invariants
architecture(ai): add grounding policy
```

## Definition of Done

A change is complete when terminology is consistent, links work, required reviews are complete, and affected ADRs are updated.
