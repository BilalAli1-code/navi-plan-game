# Supabase / Postgres layout

This directory holds SQL migrations and local Supabase project config for ProjectSim persistence (PS-004B/C).

## Migrations

| File                                                                    | Purpose                                                                          |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `migrations/20260724220000_ps004b_simulation_persistence.sql`           | `simulation_state`, `idempotency_receipts`, `event_outbox` + FORCE RLS           |
| `migrations/20260724233000_ps004c_outbox_relay_and_memberships.sql`     | Outbox relay columns, `tenant_memberships`, capability auth support              |
| `migrations/20260725010000_ps_roadmap_003_simulation_run_aggregate.sql` | Expand `simulation_state` into SimulationRun aggregate snapshot (PS-ROADMAP-003) |

Migrations are the durable schema source of truth. Apply them with the helper script or the Supabase CLI.

## Apply migrations (local / CI)

Requires a Postgres admin connection string:

```bash
export DATABASE_ADMIN_URL=postgresql://postgres:postgres@127.0.0.1:5432/projectsim_test
node scripts/apply-migrations.mjs
```

The script records applied filenames in `public.schema_migrations` and is idempotent.

For hosted Supabase projects, prefer:

```bash
npx supabase db push
# or
npx supabase migration up
```

against a linked project (`supabase link`).

## Application connection

Runtime adapters should use a **non-superuser** role (e.g. `projectsim_app`) via `DATABASE_URL`. The app sets `request.jwt.claims` per transaction so RLS policies evaluate `app_current_tenant()`.

Admin/migration connections use `DATABASE_ADMIN_URL` and must not be used by the application path.

## Database types

`packages/infrastructure/src/simulation/postgres/database.types.ts` is
**hand-maintained** today (not generated by CLI/CI).

When the schema changes:

1. Add a forward-only migration under `supabase/migrations/`.
2. Update `database.types.ts` in the same PR to match applied columns/nullability.
3. Do not claim the file was regenerated unless a deterministic generation
   command was actually run and produced a clean diff.

Follow-up: wire `supabase gen types typescript` (or equivalent) once local/CI
project linkage exists, then replace hand maintenance.

Do not invent parallel domain DTOs from these DB types.

## Incomplete legacy SimulationRun rows (PS-ROADMAP-003)

Ownership columns (`learner_id`, `business_case_id`, `content_package_version_id`,
`runtime_version`) may remain NULL for pre-aggregate rows. Detect them with:

```sql
select * from simulation_state_incomplete_ownership;
```

Repair by supplying real identifiers (never invent):

```sql
update simulation_state
   set learner_id = '<learner>',
       business_case_id = '<case>',
       content_package_version_id = '<cpv>',
       runtime_version = '<runtime>'
 where tenant_id = '<tenant>'
   and simulation_run_id = '<run>';
```

Application rehydration fails closed with `SIMULATION_RUN_LEGACY_INCOMPLETE`.

## Outbox relay

`event_outbox` rows are written in the same transaction as command acceptance. Production continuous delivery runs in `@projectsim/worker` (PS-ROADMAP-023), which:

1. Discovers tenants with pending outbox rows / projection targets (`DATABASE_ADMIN_URL`)
2. Calls `outboxRelay.tick()` per tenant under RLS
3. Claims and retries per-projection `projection_processing_target` rows

Manual/test tick remains available:

```ts
const module = createPostgresSimulationCommandModule({
  database: { connectionString: process.env.DATABASE_URL! },
  tenantId,
  // optional: eventBus, authorizer, membershipStore
});
await module.outboxRelay.tick();
```

Batch size / max attempts are configured when creating the relay (defaults: 50 / 5). The default sink is an in-process `EventBus`. See `docs/operations/projection-relay-runbook.md`.

## Authorization

Production modules use `createCapabilityAuthorizer` backed by `tenant_memberships`. Seed memberships for test tenants before exercising denied/allowed paths. Tests that want unrestricted access can still inject `createPermitAllAuthorizer()`.
